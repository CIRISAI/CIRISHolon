# holon-campaign — what the reviews of 2026-11-23 owe this harness

**A NOTE, NOT CODE. NOTHING HERE IS BUILT.** Written on a day with no cargo on the shared
box. No Rust source in this crate was edited; nothing below has compiled. The first build
that adds any of it is the first time it exists. The checks themselves are already running
in Python (`Audit/prereview_check.py`, with tests), on a convention a draft carries in
fenced `prereview` blocks (`Audit/PREREVIEW.md`). This note says which of them belong HERE,
as types that make the defect unwritable, and which do not.

## Why the harness

This crate's own header says its failures "have been in the harness and not in the physics",
and it already refuses two of the things a reviewer found again this week:

- `plant::Plant::pre_check` returns `StakeUnreachable` when the observable's analytic
  `reach` is short of the stake, with no measurement (FLUID-1's lesson). SEAM-NS-0's open
  plant P2 was exactly that — `0.14` and `0.25` on paper against the `0.3` it had to
  exceed (`conformance/water_observatory/SEAM_NS0_REVIEW.md` §1) — and it reached a
  reviewer because a draft is prose and prose does not call `pre_check`.
- `stake::Stake::derived` keeps the `ReadInput`s and the arithmetic of a bar.

So the first lesson is not a new type. It is that the DRAFT must be written against the
harness's shapes before it is prose. The `prereview` block is that: the same shapes, as
data, before any instrument exists.

## What maps cleanly, and what the first build must add

| pre-review check | today in this crate | what the first build adds |
|---|---|---|
| (a) a separation table per stake; bars at least a margin from every cell; the hypotheses the stake must separate not sharing a region | nothing: `Stake` is ONE number with its provenance. A stake can be constructed with no statement of what the graded quantity reads under any hypothesis | `stake::Separation { regions, margin, margin_arithmetic, rows, separates }` and a constructor `Stake::graded(name, separation, ...) -> Result<Stake, SeparationRefusal>`. A graded stake cannot be built without it. `SeparationRefusal` names the same cases as the Python: `BarWithinMargin { region, edge, row, distance }`, `RowLandsElsewhere`, `HypothesesShareRegion { a, b, region }`, `RegionUnreached`, `MarginUnstated`. The record writer refuses a record whose graded stake carries no `Separation`, as it refuses an unlabelled typed stake today |
| (b) a plant's paper value inside the region it must reach, by the margin | `Plant::new` takes `reach` and `reach_arithmetic`; `pre_check` compares `reach.abs()` with `stake.value.abs()` | three gaps. (1) SIDE: the comparison is by magnitude, so a CLOSED plant — one that must stay under a bar — cannot be expressed; a plant should name the region it must land in. (2) MARGIN: a reach `0.001` over the stake passes; it should clear by the stake's margin or return `ReachWithinMargin`. (3) RANGE: a paper value is often a range over the carrier's noise; `reach` should be a `(low, high)` and both ends must land |
| (c) exactly one branch per outcome | `gate::Gate::branch(letter)` records the branch entered; nothing declares the outcome space | a `Branches { outcomes, rules, first_match }` value checked at construction by enumeration (the Python caps it at 200,000 outcomes), and `Report` refusing a campaign whose entered branch is not the one its outcomes select. This is the smallest of the four and is pure data |
| (e) a reserved region against the campaign's own points, after the shift | nothing | `reserve::Reserve { region, meaning, shifts, known_inside }` and `Reserve::admits(&[Point]) -> Result<(), Breach>`, called by the runner with every point it is about to compute BEFORE it computes one, so a breach is a refusal to run and not a finding afterwards. The shift is a function the campaign supplies (`fn(&Point) -> Point`), not an expression string: the Python evaluates arithmetic text because a draft is text |

## What does NOT belong here

- **(d) cited numbers occur in the file cited.** `stake::read_input` already reads a number
  out of a record by path and field and refuses when either is absent; that is stronger than
  a substring match and it is the instrument's job at run time. The Python check is for
  drafts, where there is no instrument yet.
- **A default margin.** This crate "holds no constant". The margin is the campaign's, with
  its arithmetic, as a `ReadInput`-derived value: the reading's own standard error on the
  carrier of record. A margin typed in is a typed stake and gets the same label or refusal.
- **Anything about prior art, blindness, the forcedness of a prediction, or the regime a
  constant was measured in.** Those were most of what the reviewers found and none of it is
  a type.

## The order of the first build, as tasks

1. `Separation` and `Stake::graded`, with the five refusals, and plants for each (a
   planted bar beside a cell; a planted shared region) in this crate's own tests.
2. `Plant` naming its region, with side, margin and range; `pre_check` extended; the
   existing `StakeUnreachable` cases still returned for the existing callers
   (`fluid1_lattice.rs`, `liquid1.rs`, `ct2_harvest.rs` must keep passing untouched, as
   this crate's header promises).
3. `Branches`, and `Report` checking the entered branch.
4. `Reserve`.
5. One fixture shared by both sides: the JSON of `Audit/prereview_fixtures/` parsed by a
   test here, so that the Python check and the Rust types are shown to refuse the same
   drafts for the same reasons. Until that test exists the two can drift, and the Python
   is the one that has been run.
6. `ci-gates.sh` already counts this crate's tests; no new gate is needed for 1 to 4.

and not wired; this note exists so that nobody reads it as wired).
